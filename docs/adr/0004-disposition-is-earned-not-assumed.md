# Disposition is earned, not assumed

The Delivery route serves private Media Assets from the application's own origin, so anything rendered inline there runs in the panel session's security context. Rather than serving `inline` by default and blocklisting the types known to be dangerous, the plugin inverts the rule: a response is `inline` only when the asset's mime type is not active content **and** its `mime_source` is `sniffed` or `header`. An extension-derived type asserts only that a filename ended in `.jpg`, which is not a basis for executing its contents in the panel's origin.

Two consequences are deliberate rather than accidental. A freshly imported library renders as downloads until `media:resolve-mimes --sniff` has run, which is why that command is documented as the second step of a migration rather than optional cleanup. And active content cannot be uploaded to a field with public placement at all, because a public asset resolves straight to the disk URL for rendering and passes through the route only to be saved, which is the one disposition the rule never has to argue about; the combination is refused at upload rather than silently downgraded to private, since placement is a deliberate field-level decision.

The rejected alternative was a pure type denylist on disposition. It is simpler and needs no migration step, but it trusts a filename supplied by whatever legacy system the assets came from, and it fails open in exactly the case the rule exists for.
